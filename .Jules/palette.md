## 2024-09-11 - Accurately Syncing `aria-expanded` with Visibility Classes
**Learning:** When managing component visibility using Tailwind's `hidden` class in vanilla JS, the variable checking the class's presence (e.g., `const isOpen = !element.classList.contains('hidden')`) represents the state *before* the toggle. Assigning `isOpen` directly to `aria-expanded` causes the screen reader state to be inverted relative to the visual state. Additionally, missing `focus-visible` classes on interactive elements in Tailwind projects often leave them without visible keyboard focus.
**Action:** When using `classList.toggle('hidden')`, map the *inverted* previous state (`!isOpen`) to `aria-expanded` to reflect the new state. Also, always verify that every interactive element has explicit `focus-visible` outline styles, such as `focus-visible:ring-2 focus-visible:ring-brand-teal focus-visible:outline-none`, since Tailwind resets default browser focus outlines.
