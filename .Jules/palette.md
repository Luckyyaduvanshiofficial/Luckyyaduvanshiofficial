## 2024-10-27 - Ensuring Dynamic aria-expanded Matches Visibility State and Restoring Tailwind Focus Outlines
**Learning:** When managing toggleable UI elements like mobile menus, `aria-expanded` attributes must dynamically reflect the true visibility state (e.g., presence of a `hidden` class) across *all* code paths that can trigger visibility changes, such as clicking the toggle button *and* clicking internal navigation links that close the menu. Additionally, Tailwind CSS's default styles remove native browser focus outlines, meaning interactive elements require explicit utility classes (like `focus-visible:ring-2 focus-visible:ring-brand-teal focus-visible:outline-none`) to remain keyboard accessible.
**Action:** When implementing or auditing custom JavaScript UI toggles (menus, accordions, dialogs) in this repository, rigorously verify that `aria-expanded` is strictly mapped to the visibility class toggles and covers all closing events. Always audit interactive elements (buttons, links) for explicit `focus` or `focus-visible` styles to ensure keyboard navigation remains visible despite Tailwind's reset.
