## 2024-08-20 - Syncing ARIA States with Utility Classes
**Learning:** When using utility-first frameworks like Tailwind CSS, visually toggling elements (e.g., via `.hidden`) does not natively communicate state changes to screen readers. Relying solely on CSS classes leaves a gap in accessibility, particularly for toggleable menus or accordions. Additionally, Tailwind resets default browser focus outlines for cross-browser consistency, making interactive elements invisible to keyboard users unless focus states are explicitly styled.
**Action:** Always map interactive visibility states (e.g., toggling `.hidden`) directly to dynamic `aria-expanded` attributes in JavaScript, updating it across *all* user action pathways (e.g., closing via an internal link vs the main button). Furthermore, explicitly append `focus-visible:` utilities (like `focus-visible:outline-none focus-visible:ring-2`) to all custom interactive components to restore keyboard navigability.
